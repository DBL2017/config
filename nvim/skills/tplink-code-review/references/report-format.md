# Non-module report format

Apply only to file, selection, diff, commit and Gerrit reviews. Scope-resolution
failures in SKILL.md take precedence. Module reports are generated by
`scripts/generate_review_report.py` under the module completion protocol.
Deliver non-module reports directly in chat; do not create a report file.

Write explanatory prose in Simplified Chinese. Start with `结论：通过` or
`结论：需要修改`. If material context is inaccessible and no confirmed finding
supports a change request, use `结论：无法完成评审` and name the limitation.

Without an available spec, use one findings list sorted Critical, High,
Medium, Low. With an actual spec, use `## Standards（规范符合性）` and
`## Spec（需求符合性）`, including both; write `未发现明确问题。` for an empty
axis. Sort each independently and do not duplicate root causes.

```text
- [Severity] 文件:行号：问题标题
原因：说明风险及触发条件。
建议：给出最小、具体、可验证的修复方向。
规则：注明对应的评审类别或 TP-LINK 规范章节（如适用）。
```

Use the changed line best identifying a diff cause, or current-source line
for file reviews. Without reliable line numbers, identify the function or
fragment instead of guessing.

With no confirmed findings and no material blocker, return exactly:

```text
结论：通过
未发现明确的功能、安全、稳定性或规范问题。
```

For a two-axis review with neither axis having findings:

```text
结论：通过

## Standards（规范符合性）
未发现明确问题。

## Spec（需求符合性）
未发现明确问题。
```

Append `评审范围：...` only for material missing context or validation limitations.
Do not add a generic summary, praise, patch, checklist or reasoning transcript.
