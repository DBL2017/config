# C/C++ 编程规则

本规则用于 C/C++ 代码生成、修改和审查。格式化以项目 `.clang-format` 为最终依据；本文件中的格式化要求与其冲突时，以 `.clang-format` 为准。

## 1. 格式化

- 适用于 `.c`、`.cc`、`.cpp`、`.cxx`、`.h`、`.hh`、`.hpp` 等文件。
- 缩进宽度为 4；Tab 宽度为 4，按 `AlignWithSpaces` 规则处理。
- 每行最多 120 个字符；超长表达式在低优先级运算符处换行。
- 最多保留一个连续空行；不主动关闭格式化。
- 命名空间内容缩进一层；`case` 标签不额外缩进；大括号不额外缩进。
- `class`、`enum`、`struct`、`union`、函数、命名空间和控制语句的大括号另起一行。
- `else` 和 `catch` 前的大括号另起一行。
- `if`、`for`、`while`、`do`、`switch` 必须使用大括号，且控制语句不得与执行语句写在同一行。
- 短代码块、短 `case`、短 `if` 和短循环不合并为单行；仅空函数可保持单行。
- 控制语句关键字与左括号之间保留空格：`if (condition)`。
- 普通函数调用和声明与左括号之间不加空格。
- 圆括号、方括号和空括号内不加空格；尖括号和容器字面量按 `.clang-format` 保留空格。
- 指针和引用与右侧类型对齐：`int *value`、`const T &value`。
- C 风格类型转换的括号内不加空格，转换后不加额外空格。
- 连续赋值的等号、连续声明的变量名和行尾注释按规则对齐。
- 非赋值二元运算符和三元运算符在运算符前换行。
- 构造函数初始化列表使用 4 个字符缩进。
- 函数参数默认紧凑排列，仅在超出行宽或格式化要求时换行。
- C++ 列表初始化的大括号内不去除空格。

```cpp
if (condition)
{
    process_item();
}
else
{
    recover_item();
}
```

## 2. 注释

- 源代码中的注释必须使用英文；不要新增中文注释。
- 注释必须与代码保持一致；修改或删除代码时同步修改或删除注释。
- 优先说明原因、约束和风险，不重复代码已经表达的内容。
- 注释与代码采用相同缩进，置于代码上方或行尾。
- 复杂表达式、位操作、平台相关代码和 workaround 必须说明原因。
- 空循环体和空函数体必须说明意图。
- 行尾注释与代码之间保留 2 个空格。
- `IWYU pragma` 注释保持原样，不拆分、不改写。
- 故意的 `switch` fall-through 必须添加 `/* fall through */` 注释。

```cpp
// Retry because the device may still be completing the previous transfer.
retry_transfer();
```

## 3. 命名与作用域

- 命名必须清晰表达用途，遵循项目既有风格。
- 函数和变量使用小写加下划线；宏和常量使用全大写加下划线。
- 全局变量使用 `g_` 前缀；仅本文件使用的变量和函数使用 `static`。
- 除循环变量外，不使用无意义的单字符变量名。
- 禁止局部变量与全局变量同名。
- 函数名使用清晰的动宾词组；互斥操作使用一致的命名，例如 `open/close`、`lock/unlock`。
- 变量在最小作用域内声明，并尽量在声明处初始化。
- 不返回指向局部变量的指针或引用。

## 4. 函数与表达式

- 函数应职责单一，尽量控制在 200 行以内；避免高复杂度、多用途和不必要的递归。
- 函数返回值必须语义清晰；调用有返回值的函数时必须使用或明确处理返回值。
- 所有错误返回码必须处理。
- 所有参数以及来自全局变量、文件等的外部输入必须进行有效性检查。
- 使用括号明确表达式顺序，不依赖容易误读的默认优先级。
- 特别检查 `=`/`==`、`&`/`&&`、`|`/`||` 和 `<`/`<=` 等易混淆运算符。
- 只读指针参数使用 `const`；避免不必要的类型转换，并明确处理符号扩展、溢出和平台差异。

```c
uint16_t value = (uint16_t)(((uint16_t)high << 8) | low);

if ((flags & READABLE) != 0U)
{
    read_data(buffer, buffer_size);
}
```

## 5. 内存、资源与字符串安全

- 禁止使用未初始化的变量。
- 所有内存申请、文件打开和其他资源获取都必须检查结果。
- 资源必须在所有退出路径释放或关闭；禁止内存泄漏、重复释放、悬空指针和释放后使用。
- 防止数组越界、指针越界、整数溢出、整数下溢和差 1 错误。
- 字符串必须以 `'\0'` 结尾，并使用带长度限制的操作。
- 禁止使用 `gets`；谨慎使用 `strcpy`、`strcat` 和 `sprintf`，优先使用 `snprintf` 等有边界检查的接口。
- 使用 `snprintf` 时检查返回值，识别输出截断。
- 使用 `strncpy` 时确认是否需要手动补充结束符。
- 计算数组大小使用 `sizeof(array)`；注意数组传参后会退化为指针。
- 多任务环境下，可重入函数不使用 `static` 局部变量；必须共享全局状态时使用适当的同步机制。

```c
int format_name(char *destination, size_t destination_size, const char *source)
{
    int result;

    if ((destination == NULL) || (source == NULL) || (destination_size == 0U))
    {
        return -1;
    }

    result = snprintf(destination, destination_size, "%s", source);
    if ((result < 0) || ((size_t)result >= destination_size))
    {
        return -1;
    }

    return 0;
}
```

## 6. 控制流

- `switch` 必须包含 `default` 分支；确实无需处理时应明确说明原因。
- 每个 `case` 必须 `break`、`return` 或明确标注 fall-through。
- 条件分支必须覆盖错误和异常路径，不得静默忽略非法输入。
- 多线程子线程应主动返回，不强制终止线程。

## 7. 头文件、包含和宏

- 头文件必须有 include guard 或项目规定的等效保护。
- 头文件只放必要的声明、类型、宏和 `extern` 声明，不放不必要的定义。
- 只包含必要的头文件，减少编译依赖。
- `#include` 按项目 `.clang-format` 排序；通常为自身头文件、系统头文件、第三方头文件、本项目头文件。
- 项目中 `llvm`、`llvm-c`、`clang`、`clang-c` 头文件归入优先级 2；系统头文件及 `gtest`、`isl`、`json` 头文件归入优先级 3；其他头文件归入优先级 1。
- 宏表达式和宏参数必须使用完备括号，避免参数重复求值和副作用。
- 多语句宏使用 `do { ... } while (0)`。
- `foreach`、`Q_FOREACH`、`BOOST_FOREACH` 识别为 foreach 宏。
- 未配置宏块标记时，不把其他宏假定为格式化代码块。

```c
#define RESET_PAIR(first, second) \
    do                             \
    {                              \
        (first) = 0;               \
        (second) = 0;              \
    } while (0)
```

## 8. Objective-C

- Objective-C 块缩进为 4。
- `@property` 后不加额外空格。
- Objective-C protocol 列表前加空格。
- Objective-C 声明的大括号另起一行。

## 9. 可测性与审查

- 调试开关和日志接口在项目内统一；日志至少包含模块名和行号。
- 使用 `#ifdef DEBUG` 等方式控制调试代码，正式版本关闭调试开关，且开关不能改变功能行为。
- 为新增和修改的逻辑设计单元测试，至少覆盖主要语句和错误路径。
- 统一编译选项；编译告警必须修复，或通过带原因说明的 `#pragma` 明确处理。
- 代码审查必须检查格式、命名、注释、功能正确性、稳定性、安全性和可测试性。
- 不随意修改其他模块的配置、常量和接口；使用系统接口前确认字节序、内存归属和生命周期约定。

## 10. 优先级

代码质量优先级如下：

1. 正确性
2. 稳定性与安全性
3. 可测试性
4. 可读性与规范
5. 全局效率
6. 局部效率

只有在不损害前述质量的前提下进行性能优化。循环中应减少重复工作，将循环不变量移出循环，并尽量减少循环嵌套。

## 11. 生成与审查清单

- [ ] 已按项目 `.clang-format` 格式化，缩进为 4，行宽不超过 120。
- [ ] 控制语句使用大括号，`switch` 有 `default`，fall-through 有明确注释。
- [ ] 命名清晰，作用域最小，局部变量已初始化。
- [ ] 指针、引用、`const` 和类型转换使用正确。
- [ ] 错误返回值、输入参数和异常路径已处理。
- [ ] 内存、文件和其他资源在所有退出路径正确释放或关闭。
- [ ] 数组、指针、整数和字符串操作经过边界检查。
- [ ] 没有未初始化变量、内存泄漏、悬空指针、越界访问或释放后使用。
- [ ] 宏有完备括号，多语句宏使用 `do { ... } while (0)`。
- [ ] 头文件有保护，包含项最小且顺序正确。
- [ ] 复杂逻辑、平台差异和 workaround 有原因注释。
- [ ] 新增或修改逻辑具备相应测试，编译告警已处理。

## 12. 格式化命令

```bash
clang-format -style=file -i <source-file>
```
