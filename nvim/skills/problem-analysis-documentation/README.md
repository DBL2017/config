# Problem Analysis and Documentation

这个 Skill 用于对软件故障、缺陷、崩溃、回归等异常行为进行证据驱动的排查。它帮助用户从现象和材料出发，逐步定位原因、评估修复方案，并在需要时形成可归档的问题分析报告。

## 工作原理

### 1. 判断是否适用

当用户报告或要求调查 bug、事故、崩溃、回归或其他异常行为时，Skill 会参与处理。一般代码讲解、没有具体故障背景的常规代码审查，以及与缺陷无关的新功能开发，不需要走完整的问题分析流程。

### 2. 根据需求选择响应模式

Skill 会结合用户的诉求、问题影响和现有证据选择模式；不同模式可以组合。

| 模式 | 适用场景 | 默认交付 |
|---|---|---|
| 快速排查 | 简单问题、初步定位 | 当前结论或未知状态，以及最有价值的下一步检查 |
| 根因分析 | 用户要求解释原因，或问题需要深入调查 | 证据、因果链、置信度、候选假设、修复建议和验证方案 |
| 实施修复 | 用户明确要求修复或实现 | 经检查后进行针对性修改，并报告实际运行的检查及结果 |
| 正式报告 | 用户要求归档，或问题影响/审计需要较高 | 使用完整报告模板，记录范围、证据、根因、方案、验证和行动项 |

简单排查默认不会生成完整报告。仅要求诊断或解释，也不代表授权修改代码。

### 3. 按需收集并验证证据

分析时，Skill 会根据问题复杂度检查相关源码、日志、配置、版本和复现步骤；保护敏感信息，区分事实、推断和未知项。证据不足时不会补造事实，而是说明缺口，并给出最小的补充信息或验证步骤。

深入分析会尝试建立以下因果链：

> 触发条件 → 代码机制 → 失效或状态异常 → 用户症状与影响 → 未能及时发现的原因

日志中的最后一条错误或可疑代码行本身不作为根因证明。无法复现时，会说明限制并使用静态追踪等可用证据。

### 4. 按请求提供修复和文档

只有用户明确要求实施时，Skill 才会修改代码。修改前检查相关文件和现有差异；修改后运行适用的测试或检查，并区分“已运行”和“建议运行”的项目。

正式报告使用 [`references/report-template.md`](references/report-template.md)。快速排查和常规根因分析则按对应模式输出，不强制填满报告模板。

## 使用方法

描述问题时，尽可能提供以下信息；简单排查不需要一次提供全部内容：

- **现象：** 实际发生了什么，错误信息是什么？
- **预期：** 原本应该发生什么？
- **范围：** 影响哪些版本、平台、设备或请求？
- **时间与复现：** 何时开始、发生频率、最小复现步骤是什么？
- **证据：** 相关源码路径、脱敏日志、配置、提交、测试结果或版本信息。
- **诉求：** 希望快速定位、深入分析、直接修复，还是生成归档报告？

请在分享前移除密码、令牌、私钥、客户个人信息等敏感内容。信息不完整时，Skill 会先指出限制；若仍能推进，会在明确假设的前提下继续。

## 具体用例

### 用例一：简单排查，只要结论和下一步

**请求示例**

> 本地运行服务时偶尔出现 `connection refused`，通常重试就恢复。可能是什么方向？先告诉我最值得检查的一项。

**响应方式**

进入快速排查：简要说明当前能确认的情况或尚不能确认根因，并给出最有价值的下一步检查；不自动生成完整报告，也不修改代码。

### 用例二：根据源码和日志分析根因

**请求示例**

> 最近一次版本升级后，某 API 偶尔返回 500。下面附上处理请求的源码、两段脱敏日志和版本差异。请判断根因是否能确认；如果不能，列出最可能的假设和如何验证。

**响应方式**

进入根因分析：对照日志与源码路径，找出行为偏离点，建立因果链，区分已证实结论和待验证假设，并给出验证步骤和修复建议。不会仅凭日志最后一行就断言根因。

### 用例三：明确要求修复并增加回归测试

**请求示例**

> 请修复这个配置解析 bug：空配置项会导致进程崩溃。检查相关实现和现有测试，添加回归测试，并运行对应测试。

**响应方式**

进入根因分析与实施模式：先检查实现和当前改动，再针对根因修改代码和测试；最后报告变更文件、实际运行的测试及结果。若测试无法运行，会说明具体阻塞，不会将未运行的测试描述为通过。

### 用例四：生成可归档的问题报告

**请求示例**

> 设备重启后配置丢失，影响多个设备。请根据我提供的启动日志、配置读写代码、设备版本和复现步骤分析原因，并按报告模板生成一份可归档的问题分析报告。

**响应方式**

进入根因分析与正式报告模式：整理问题范围、证据和时间线，分析根因及置信度，提出缓解与永久修复方案、验证方法、发布/回滚建议，并填写行动项。没有证据支持的模板字段会标为未知或待补充。

### 用例五：不需要完整故障分析的请求

**请求示例**

> C 语言里 `strncpy` 和 `snprintf` 有什么区别？

**响应方式**

这是一般知识讲解，不是具体异常行为排查，因此直接解释即可，不需要启动完整的问题分析流程。
